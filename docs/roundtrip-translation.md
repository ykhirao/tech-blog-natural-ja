# 往復翻訳で、語の対応関係を辿る

日本語 → 英語 → 日本語 と往復させて、どの語がどの語に置き換わるかを集める。

ねらいは「同じ概念に複数の日本語があるとき、翻訳器がどれを選ぶか」を見ること。
実データで観測した多極化([metaphor-vocabulary.md](metaphor-vocabulary.md))と
突き合わせると、語の対応関係が辿れる。

- 実施日: 2026-09-14
- 翻訳: 手元の `pid`(`pi --provider ollama-cloud --model deepseek-v4-flash:cloud`)
- 実装: `scripts/roundtrip_queue.py`

## 最初の1件で仮説が裏づけられた

```
元:   システムの土台となる部分を切り分けて、境界を明確にします。
英訳: Separating out the foundational parts of the system and clarifying the boundaries.
戻し: 基盤となる部分を切り分けて、境界を明確にすること。
```

**「土台」→「基盤」** に変わった。この2語は同じ概念グループで、
実データでは両方とも増えている。

| 語 | 2015 | 2026 |
|----|------|------|
| 土台 | 0.12% | 6.87% |
| 基盤 | 0.46% | 13.01% |

翻訳器が両者を行き来したことで、**互いに置き換え可能**だと確認できた。

## 「入口」が最も鮮明

```
元:   がpackageの入口、が再利用する手順、がMCP接続の設定面です。
英訳: The entry points of the package, ...
戻し: パッケージのエントリポイント、再利用する手続き、...
```

**「入口」→「エントリ」に戻った。** これは実データで辿った系譜と方向が逆。

| | 2015年 | 2026年 |
|---|--------|--------|
| エントリ | 1.87%(シェア**100%**) | 1.28% |
| **入口** | **0.00%** | **2.52%**(首位) |

2015年は「エントリ」しか存在しなかった。翻訳器は「入口」を英訳すると
`entry point` にし、戻すと「エントリ」に帰る。

つまり**「入口」は英語に対応物を持つ和語**で、翻訳を介すと外来語に引き戻される。
2026年の「入口」は新しい選択だったと裏づけられる。

## 記事まるごとだと、もっと動く

1文だけでなく地の文をまるごと往復させると、語の置き換わりが増える。

```
1,199字の記事(含む語: 仕組み・入口・確認)を往復
→ 入口 → ベース, エントリ, ツール, 検証
```

文脈が長いぶん、翻訳器の語選択が広く出る。実態に近いのはこちら。

## 仕組み

5,000件規模を並行実行しても壊れないようにした。

```bash
# 1. 仕事を作る
./scripts/roundtrip_queue.py build --count 5000 --mode article

# 2. 処理する(複数プロセスを同時に走らせてよい)
./scripts/roundtrip_queue.py work &
./scripts/roundtrip_queue.py work &
./scripts/roundtrip_queue.py work &

# 3. 進捗と集計
./scripts/roundtrip_queue.py status
./scripts/roundtrip_queue.py report
```

### 壊れない仕組み

- **ファイルロック**(`fcntl.flock`)で仕事を取り出す。
  ロック中に完了済みを読み直すので、同じ仕事を二重に処理しない
- **追記のみ**。途中で落ちても完了分は残る
- **レジューム**。再実行すると未処理だけ拾う
- **15分以上応答のない仕事**は `status --reset` で未処理に戻せる

実際に2プロセスを同時に走らせて検証した。

| 項目 | 結果 |
|------|------|
| 仕事 | 12件 |
| 完了 | 6件(2プロセスが3件ずつ) |
| **重複** | **0件** |
| 失敗 | 0件 |

### 2つのモード

| モード | 対象 | 速さ | 用途 |
|--------|------|------|------|
| `sentence` | 対象語を含む1文 | 速い | 語の対応関係を大量に集める |
| `article` | 地の文まるごと(既定2,000字) | 遅い | 実態に近い。文脈込みの変化を見る |

## この手法の限界

**検出しているのは「翻訳器が揺らす語」であって「AIが好んで使う語」ではない。**

今回は実データの発見(エントリ → 入口の多極化)と独立に一致したので
価値があったが、単独では証拠にならない。

- 翻訳器のモデルが変われば結果も変わる
- 1回の往復では、たまたまその語が選ばれただけの可能性がある
- 記事本文を外部(ollama-cloud)に送る。公開記事なので問題は小さいが、
  完全にローカルで済ませたいなら Argos Translate という選択肢がある

## 未検証

- 語ごとの「生き残り率」(往復しても同じ語が残る割合)。
  `report` に実装済みだが件数が足りない
- 年による違い。2015年の記事と2026年の記事で、往復の挙動が変わるか
