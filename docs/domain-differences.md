# 分野によって文体は違うのか

参照プロファイルを分野別に分けるべきか判断するために測った記録。

きっかけは、変換プロンプトの検証で**漢字割合だけが p95 のまま下がらなかった**こと
([prompt-evaluation.md](prompt-evaluation.md))。
そのとき「技術用語は漢語が多くひらけないから」と説明したが、
**これは実測で反証された。**

- 実施日: 2026-09-14
- 対象: Qiita 2020年8月 6,952本 / 2026年8月 10,264本
- 分野はタグから機械的に束ねた(単一タグでは記事数が足りないため)

## 結論: 分野別に分ける必要はない

分野差は小さく、時代差のほうが大きい。

| 比較 | 漢字率の差 |
|------|----------|
| 分野間(2020年、7分野) | **0.030** |
| 時代間(2020 → 2026) | **0.054** |

**時代差が分野差の約2倍。** しかも分野を揃えて比べても、全分野で上がっている。

| 分野 | 2020 | 2026 | 差 |
|------|------|------|-----|
| Web frontend | 0.173 | 0.234 | **+0.061** |
| Mobile | 0.161 | 0.224 | **+0.063** |
| Python/ML | 0.192 | 0.245 | **+0.054** |
| 初心者 | 0.188 | 0.235 | **+0.048** |
| Infra/Cloud | 0.162 | 0.207 | **+0.045** |

例外なく上昇。**「技術用語が多いから漢字率が高い」では説明できない。**

## 分野ごとの文体(2020年 = AI以前)

| 分野 | 記事数 | 漢字率 | burstiness | 体言止め | 平均文長 |
|------|-------|-------|-----------|---------|---------|
| Python/ML | 992 | 0.192 | -0.220 | 0.160 | 33.5 |
| 初心者 | 357 | 0.188 | -0.226 | 0.156 | 30.5 |
| Enterprise | 372 | 0.175 | -0.222 | 0.155 | 35.0 |
| Web frontend | 864 | 0.173 | -0.234 | 0.141 | 33.4 |
| Web backend | 982 | 0.169 | -0.229 | 0.173 | 31.5 |
| Infra/Cloud | 793 | 0.162 | -0.249 | 0.146 | 36.2 |
| Mobile | 604 | 0.161 | -0.247 | 0.148 | 36.1 |
| **全体** | 6,952 | **0.174** | **-0.234** | **0.155** | **34.3** |

差はあるが小さい。最も硬い Python/ML(0.192)と最も柔らかい Mobile(0.161)で
0.031 しか違わない。**単一のプロファイルで足りる。**

burstiness はさらに差が小さく、-0.220 〜 -0.249 の範囲に収まっている
(全体の中央値 -0.234)。体言止めも 0.141 〜 0.173。

## 2026年も同じ構図

| 分野 | 漢字率 | burstiness | 体言止め |
|------|-------|-----------|---------|
| Python/ML | 0.245 | -0.295 | 0.038 |
| 初心者 | 0.235 | -0.285 | 0.047 |
| Web frontend | 0.234 | -0.317 | 0.033 |
| Enterprise | 0.228 | -0.289 | 0.035 |
| Mobile | 0.224 | -0.313 | 0.041 |
| Web backend | 0.222 | -0.287 | 0.031 |
| Infra/Cloud | 0.207 | -0.270 | 0.051 |

分野間の幅は 0.039 で、2020年(0.030)とほぼ変わらない。
**体言止めは全分野で 0.03〜0.05 まで落ちている**(2020年は 0.141〜0.173)。
分野を問わず一様に減った。

## 前の説明を訂正する

[prompt-evaluation.md](prompt-evaluation.md) にこう書いた。

> **漢字割合は技術記事では下げにくい。** 専門用語は漢語が多く、
> ひらくと逆に読みにくくなる。

**この説明は不十分だった。** 専門用語の密度が高い分野(Python/ML)と低い分野
(Mobile, Infra)を比べても差は 0.03 しかなく、同じ分野内で時代差 0.05 が出ている。

漢字率の上昇は専門用語ではなく、**地の文そのものが漢語寄りになった**
ことを示している。語彙分析([vocabulary-shift.md](vocabulary-shift.md))で
「設計」「検証」「運用」「判断」といった漢語が増え、
「色々」「とりあえず」「感じ」といった和語が減っていたのと整合する。

つまり漢字率は**下げられる**。専門用語ではなく、地の文の語彙を
和語に寄せればよい。変換プロンプトの指示は妥当だった。

## Infra/Cloud だけ少し違う

どの年でも Infra/Cloud が最も漢字率が低く(2020: 0.162 / 2026: 0.207)、
burstiness も最も高い(単調でない)。平均文長も長い。

コマンドや設定ファイル名が多く、地の文が「〜を実行します」のような
和語中心になるためと考えられる。ただし**この解釈は未検証**。

## この分析の限界

- **タグの束ね方は手作業**。「Web frontend」に何を入れるかで結果は動く。
  また1記事に複数タグが付くので、分野は排他ではない。
- **タグが実態を表すとは限らない**。「初心者」タグは内容の難易度ではなく
  書き手の自己申告。
- **分野の構成が年で変わっている**。2026年は Python/ML(1,128本)と
  Infra/Cloud(1,044本)が増え、Web backend(384本)と Mobile(257本)が減った。
  全体の平均はこの構成比の影響も受ける(ただし分野内比較では影響しない)。
